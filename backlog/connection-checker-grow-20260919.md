
# リロードせずに再取得し、直前の結果からIPと国が変わったかを示す

いまの画面は開いた瞬間に1回だけ `/api/whoami` を呼ぶので、VPN や回線を切り替えたあとはページをリロードしないと新しいIPが見えない。リロードすると切り替え前の値は画面から消えるため、「本当に出口が変わったか」は利用者が前のIPを覚えておくか別の場所に控えて見比べるしかない。「再取得」ボタンで `/api/whoami` を呼び直し、直前の取得結果と比べて「IPが変わりました（前回 203.0.113.5）」「変化なし」をIPと国について表示する。直前の1件はページ内のメモリにだけ持ち、保存はしない。リロードすれば消える。切り替え前後の見比べという、このアプリを開く理由そのものが画面の中で完結する。

## 意図

VPN のオン・オフや回線の切り替えをした人が、その直後に「出口のIPと国が切り替わったか」を同じ画面のまま確かめるために使う。
前後の値を自分で覚えて見比べる手間と見間違いをなくすため。履歴は残さず、比べるのは直前の1回だけ。

## 受け入れ条件の種

- `/api/whoami` が1回目に ip `203.0.113.5`・country `JP`、2回目に ip `198.51.100.7`・country `US` を返すとき、「再取得」ボタンを押すと `ip-address` に `198.51.100.7`、接続元の国に `US` が表示され、新しい別要素に「変わりました」と前回の値 `203.0.113.5`・`JP` が表示される
- 2回とも同じ値を返すときは、再取得後にその要素へ「変化なし」と表示される。初回取得の直後（まだ再取得していないとき）はその要素を描画しない。ページをリロードすると前回の値は残っていない
- 再取得が失敗したときは直前のIP・国・送信ヘッダの表示を消さずにエラー文言を表示する。`ip-address` / `copy-feedback` / `header-list` / `fetch-error` の testid とその要素の文言、`/api/whoami` と `/api/health` のレスポンス形は変えず、既存のテストがすべて通る
